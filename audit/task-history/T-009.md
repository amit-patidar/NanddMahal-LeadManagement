Store the new answer in the existing CRM `looking_for` field without changing the database structure or other sync behavior. Confirm the source header used by `buy_plan`.

- Added the new exact property-price-range header and practical formatting aliases to the `looking_for` mapping.
- Retained the previous looking-for header aliases so sync remains compatible during the sheet transition.
- Mapped `buy_plan` to the updated `when_you_are_planning_to_buy?` header and retained `when_are_you_planning_to_buy?` as a transition fallback.
- Kept the existing missing-field-only update behavior, so normal sync does not overwrite populated CRM fields.
- Added an exported pure row-mapping helper for focused mapping verification.
