# T-010: Add direct manual lead entry

Date: 2026-08-26

## Request

Allow team members to add occasional side leads directly to the CRM without first adding them to Google Sheets. Plan the feature across manager, architecture, backend, frontend, and QA responsibilities before implementation.

## Team decision

Add one global **Add Lead** command beside the existing global search so it is reachable from every CRM page. It opens a focused modal and creates the lead directly in the CRM as `New`. Manual records are not written back to Google Sheets, and later sheet syncs must neither delete nor overwrite them.

All authenticated team members may add leads:

- Admins and managers may assign the new lead to any active user or leave it unassigned. The assignee selector defaults to the creator.
- Sales users do not receive an assignee selector. The server always assigns their new lead to their own authenticated account and ignores any submitted assignment value.

## Architect plan

- Reuse the existing `leads` and `lead_activities` tables; no schema migration is needed for the first version.
- Generate a server-side unique ID such as `manual:<uuid>` for the required `meta_lead_id` storage field. Never accept this identifier from the browser.
- Store the origin in the creation activity as `Added manually`; keep Google Sheet import behavior unchanged.
- Create the lead and its creation activity atomically so a partial record is not left behind.
- Keep initial status fixed as `New`. Existing Call / Update actions handle later movement to Follow Up, Site Visit, Super Interested, Rejected, or Closed.
- Treat normalized phone number as the manual-entry duplicate key. If a matching lead exists, return HTTP 409 with the existing lead ID so the UI can open that record instead of creating a duplicate.
- Keep the first version narrow. Add a dedicated `lead_source` column later only if source reporting or export becomes a confirmed requirement.

## Backend plan

- Add authenticated `POST /api/leads` before the existing `/api/leads/:id` route handling.
- Add a dedicated `createManualLead` database helper instead of routing manual input through Google Sheet import behavior.
- Required fields: `name` and `phone`.
- Optional fields: `email`, `lookingFor` (budget), `buyPlan`, `comment`, and `assignedTo` for managers/admins.
- Trim all text, validate email when supplied, require a plausible normalized phone number, enforce active assignees, and cap field lengths before database writes.
- Use the authenticated user ID for audit activity and permission decisions. Never trust a client-supplied creator or sales assignee.
- Return the created lead in the normal lead response shape so the client can open its detail view immediately.

## Frontend plan

- Add a `Plus` icon with **Add Lead** beside the global search; keep it visible on desktop and mobile without adding another sidebar section.
- Use the existing modal visual language, with a responsive two-column form that becomes one column on narrow screens.
- Fields: Name, Phone, Email, Budget / Looking For, Buy Plan, Initial Comment, and Assigned To when the user can manage leads.
- Mark Name and Phone as required. Disable submission while saving and show the API validation message inline.
- On success, close the modal and open the new lead detail. On duplicate response, show the existing lead and provide an **Open Lead** action.
- Preserve the current page and filters so Back returns the user to the page where they started.

## QA plan

- Verify admin, manager, and sales creation paths independently.
- Verify sales-created leads are always self-assigned, including a request that tries to spoof another assignee.
- Verify manager/admin assignment to active users, unassigned creation, and rejection of inactive or nonexistent assignees.
- Verify required fields, phone normalization, invalid email, field limits, double-submit prevention, and API errors.
- Verify duplicate phone detection across different phone formats and that the existing lead can be opened.
- Verify a created lead appears in New Leads, All Leads, dashboard counts, global search, and the correct sales user's account.
- Verify the creation activity, optional initial comment, WhatsApp access, assignment controls, and later status updates.
- Verify Google Sheet sync leaves manual leads unchanged.
- Verify modal layout, keyboard focus/escape behavior, text fit, and navigation/back behavior on desktop and mobile.
- Extend the isolated role/access suite and add focused manual-lead API regression coverage before deployment.

## Acceptance criteria

- Any authenticated teammate can create a valid side lead without using Google Sheets.
- Role-based assignment and visibility are enforced on the server.
- Duplicate phone submissions do not create another record.
- The new lead is immediately searchable and usable in the existing workflow.
- No existing sheet sync, status, comment, assignment, or WhatsApp behavior regresses.

## Implementation

- Added authenticated `POST /api/leads` with bounded field validation and canonical phone/email storage.
- Added atomic SQLite/PostgreSQL persistence for the lead and its activity records without a schema migration.
- Added server-generated `manual:<uuid>` IDs, `Manual Entry` origin, fixed `New` status, and optional initial comments.
- Added normalized-phone duplicate protection. PostgreSQL serializes same-phone creation attempts with a transaction advisory lock.
- Enforced sales self-assignment on the server and active-assignee validation for admins/managers.
- Added the global Add Lead command, responsive modal, role-aware assignee selector, inline validation, duplicate Open Lead recovery, saving guard, Escape close, and keyboard focus trap.
- Added `npm run verify:manual-leads` as an isolated reusable regression suite.

## Verification

- `npm run verify:manual-leads` passed 25 isolated API/database checks across admin, manager, and two sales users.
- The 35-check role/access suite and historical comment-search regression passed.
- `npm run build`, server syntax checks, and `git diff --check` passed.
- Browser QA on an isolated temporary CRM verified create/open, Back to list, duplicate recovery, Escape close, focus trapping, and correct default assignment.
- Desktop at 1440 x 1000 rendered a two-column 720 px modal with no horizontal overflow.
- Mobile at 390 x 844 rendered one column inside the viewport with no horizontal overflow; the global Add Lead command reduced to its familiar Plus icon.
