# T-013: Multiple Google Sheet sources

Date: 2026-10-19

## Request and behavior

Allow administrators to connect multiple spreadsheet tabs, keep a separate column mapping for each, and import from all enabled sources using the existing Sync Leads button.

## Implementation and data protection

- Added the additive `sheet_sync_sources` settings table for both SQLite/PostgreSQL, with unique spreadsheet/numeric-tab identity. Startup adopts the legacy environment source once without importing leads. Its numeric tab ID is pinned after the first successful selected-source read. Source settings persist across deployments; credentials stay in environment variables.
- Added admin-only source list/connect/enable APIs and selected-source mapping via `sourceId`. Existing mapping requests without `sourceId` retain their environment-source compatibility behavior.
- Connect accepts a Google Sheets URL or spreadsheet ID plus tab name, or a URL with `gid`. It verifies read access before saving and never imports leads. An explicit tab name takes precedence over `gid`; Google URLs are parsed into IDs, never fetched as arbitrary URLs.
- Newly connected sources use stable numeric tab IDs, supporting renamed tabs. Reads use Google's [spreadsheets.getByDataFilter API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/getByDataFilter) and limit mapping reads to the header plus three sample rows.
- Sync snapshots enabled sources, processes them sequentially in creation order then source ID, and returns totals plus per-source results. Source failures do not stop other sources; provider errors are replaced with a safe actionable message. The process rejects concurrent aggregate sync requests.
- Retained global stable lead IDs, existing source-field enrichment, and CRM-managed-data protections. A Lead ID shared across sources is one CRM lead. Disabling a source keeps its leads and mappings. No deletion API was added.
- Added source controls to the existing admin dashboard, with mapping selection, connection failure feedback, enable/disable controls, and per-source sync results. Unsaved mappings block switching sources, connecting/disabling sources, and syncing until saved or cancelled.
- Updated setup documentation and the disposable demo/mapping UI harness for selected sources. Historical screenshot evidence was preserved.

## Deployment and rollback

No new environment variables are needed when Google credentials are already configured. Deploy the build; startup creates the source settings table and adopts the existing configured source. Share additional spreadsheets with the existing service account, connect them in the CRM, review their mappings, and sync.

After adoption, changing the old source environment variables does not replace saved settings. Connect a new source and disable the retired one instead. Reverting the application leaves the additive settings tables intact; older builds ignore source settings and resume their single environment-configured import behavior. Reverting code does not remove leads already imported from additional sources.

No live Google Sheet, PostgreSQL database, Render deployment, Meta configuration, or production records were accessed or changed. Live integration and PostgreSQL execution remain unverified. No commit or push was performed.
