# T-004: Comment-aware lead search

Date: 2026-08-19

## Scope

Implement only comment-aware lead search. The Low Budget section and Rishi Bhaiya assignment/export work are deferred to T-005.

## Team design discussion

### Architect recommendation

- Reuse the existing `/api/leads` query path and shared table instead of creating a separate search flow.
- Keep one search box so global search and All Leads search behave consistently.

### Backend implementation

- The shared search now matches `leads.last_comment` and historical `lead_activities.comment` through an `EXISTS` condition, preventing duplicate leads.
- The endpoint returns `matched_comment` so global search can show the comment that caused the match.

### Frontend implementation

- Global search and All Leads search now clearly advertise comment search.
- Global search displays the matching comment when the API returns one.
- Existing table layout, filters, status behavior, and navigation are unchanged.

### QA verification scope

- Verify current and historical comments, partial terms such as `8k`, punctuation, empty comments, and no duplicate rows.
- Verify global search result context and All Leads table results.
- Run the build and `node tools/verify-comment-search.js` before deployment.

## Verification completed

- `node tools/verify-comment-search.js` passed against an isolated temporary SQLite database. It confirmed that a historical `8k` comment is found even when the lead's latest comment is different, with no duplicate result.
- During final PR verification on 2026-08-21, the verifier was updated to create a temporary admin session before calling the now-protected leads API. The authenticated regression check passed again.
- `npm run build` passed.
- Local UI and API health checks returned HTTP 200 at `http://localhost:5173/` and `http://localhost:4000/api/users`.
- The in-app browser visual check is unverified because the browser connector failed before connecting with an environment metadata error.
