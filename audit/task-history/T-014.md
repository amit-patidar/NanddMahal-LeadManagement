# T-014: Read-only Google Sheets scope compatibility

Date: 2026-10-19

## Report and cause

User reported `Request had insufficient authentication scopes.` on the existing production sheet after the multi-source rollout, without adding sources. The new pinned-tab path used `spreadsheets.getByDataFilter`, whose [documented authorization scopes](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/getByDataFilter) exclude `spreadsheets.readonly`. The app intentionally requests only that read-only scope. Initial legacy reads could work until the source's numeric tab ID was pinned; later reads entered the incompatible path. Mock Google responses did not enforce this endpoint/scope difference in the initial QA.

## Correction

Keep the current read-only credentials and scope. Resolve a pinned numeric tab ID using a metadata-only `spreadsheets.get`, then fetch its escaped title range using another `get`. [This method supports spreadsheets.readonly](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get). Validate the returned cells' numeric tab identity before returning any rows, so a rename/title reuse between requests cannot import a different tab. Mapping samples remain bounded to four rows; full sync reads the whole selected tab. No source settings, mappings, credentials, or lead-data migration is needed.

The public health response now includes the deployment commit from Render's standard `RENDER_GIT_COMMIT` variable, or null locally. This identifies a backend-only rollout without relying on unchanged frontend asset hashes; it exposes no credentials.

## Verification

Temporary SQLite/mocked Google checks passed for both existing suites: multi-source checks and all seven mapping groups. The multi-source mock now verifies the configured read-only OAuth scope and rejects getByDataFilter with the reported error. Added explicit GET-only metadata/data tests for escaped renamed titles, bounded preview, full sync, and rejecting a substituted tab between requests. Existing source adoption, repeated sync, protected fields, per-source mappings, failures, persistence, and access controls also passed.
