# T-011: Saved Google Sheet column mapping

Date: 2026-09-20

## Request and review

User requested team discussion of optional column mapping below Sync Leads, configured when needed and reused on later syncs. Coordinator reviewed local sync/import code; two delegated reviewers covered architecture/backend and frontend/QA. No deployed configuration, schema, or records were inspected or changed. Findings describe the local checkout, not verified production state.

## Proposed scope

- Add a collapsed Column mapping disclosure below Sync Leads with CRM field, sheet-header dropdown, and sample value.
- Expose the eight supported source fields: Lead ID, source creation date, name, phone, email, campaign, Budget / Looking For, and Buy Plan. Do not expose arbitrary database columns or CRM-managed status, assignment, comments, or scheduling fields.
- Load headers on demand, suggest current aliases, offer explicit mappings and Ignore for optional fields. Require a stable lead-ID mapping; show preview warnings for missing names/phones and invalid dates.
- Provide Preview, Save Mapping, Cancel, and Reset to automatic. Preview and Save do not import leads. Ordinary Sync uses saved configuration without prompting.
- Retain current admin-only API authorization for sync and all mapping endpoints; align frontend visibility with this rule.
- Persist versioned mapping JSON, header snapshot, revision, updater, and timestamp in a small additive settings table, keyed by spreadsheet ID and stable numeric tab ID. Existing database remains the target; MongoDB migration is outside scope.
- Resolve mappings by unambiguous header names so column reordering is safe. Reject missing mapped headers or ambiguous duplicate headers before importing. Freeze one configuration revision for each sync and detect concurrent stale saves.
- Preserve IDs and phones as strings. Lead identity remains global meta_lead_id: flag repeated source IDs, reject manual: source IDs, and highlight ID-mapping changes. Do not substitute row numbers or phone numbers for stable IDs.
- Keep current aliases when no explicit mapping exists. Import new leads and fill blank source fields; remapping is not a bulk correction of populated fields. Protect manual leads and CRM-managed data.
- The existing enrichment path calls addActivity with a sync comment, which can replace last_comment. Implementation must ensure sync bookkeeping does not overwrite the latest customer comment.
- Spreadsheet URL and tab selection remain environment-configured in this first proposal. An optional later source selector would require source validation and service-account access checks. File-based Excel upload is outside current Google Sheets scope.

## QA acceptance plan

- Mapping persists across reload, restart, and another admin login; Cancel and failed saves preserve the saved mapping.
- Preview is read-only; Save does not sync; ordinary repeated sync remains idempotent.
- Test header reorder, rename, missing/duplicate/blank headers, ignored optional fields, empty sheets, invalid dates, and string IDs/phones.
- Test spreadsheet/tab isolation, changed ID mapping, reserved manual IDs, stale saves, and mapping changes during an active sync.
- Verify anonymous and non-admin API rejection, role-based UI visibility, and no credentials returned to the browser.
- Preserve existing statuses, comments, assignments, schedules, and populated source values; verify existing automatic alias compatibility.
- Test API failures and partial sync reporting with rerun safety, keyboard access, and narrow-screen layout.

## Implementation

User approved implementation while retaining manual source updates in Render. Work is on `feature/sheet-column-mapping`.

- Added `sheet_column_mappings` via idempotent startup DDL for SQLite/PostgreSQL. Settings store mapping JSON, revision, updater and timestamp per spreadsheet/tab; explicit header names provide the saved header references. Compare-and-swap writes reject stale admin edits.
- Added admin-only mapping read, preview, and save APIs, plus a shared mapping service used by sync. Preview reads only headers and three sample rows; saving never imports.
- Added a collapsed dashboard editor with Automatic, explicit header, Ignore, Preview, Save Mapping, Cancel, Reset to automatic, missing-header messages, and concurrency guards.
- Added row-level sync diagnostics and preserved latest customer comments during source-field enrichment. Empty/ignored source cells do not write default values into existing records.
- Added isolated backend tests, a browser fixture harness, and a disposable demo server. No production data, credentials, or Render settings changed.

## Review feedback

Independent review identified numeric-tab/title race, defaults applied to ignored existing fields, and locale-dependent date parsing. Fixes bind source identity and rows in one Sheets read, separate insertion defaults from enrichment, and explicitly validate/normalize ISO and locale-ordered numeric dates.

## Deployment

No new Render variables required. Deploy the feature build; startup creates the additive settings table. Change `GOOGLE_SHEET_ID`/`GOOGLE_WORKSHEET_NAME` manually when switching sources, retain service-account access, then review mapping in CRM. Rollback the application build if necessary and leave the unused settings table intact.
